# Multi-source-of-truth audit + resolutions (beyond the dictionary)

## Context

After the dictionary single-source arc ([[dec-dictionary-single-source]]) the
owner asked: where ELSE is the same data independently hand-maintained in 2+
places (so it can drift)? A 17-agent audit (task #181, 2026-06-21) swept six axes
— model codegen, rule metadata, the AGS TYPE classifier, literal constants,
relationship logic, and miscellaneous data — and adversarially verified each
candidate (a *generated* or CI-*gated* copy is not a violation).

## What's already single-sourced (no action)

Reassuringly, everything the dictionary arc touched is generated + gated: the
typed-graph codegen (Rust `#[pyclass]`, the `.pyi` stub, the node TS classes, the
validator's `phf` tables), the AGS TYPE → canonical-type classification +
`parse_value` + display-hint format strings (`laterite-ags4-types`), and the package
version (bump-my-version). The relationship *logic* (parent chains, shared-keys,
depth-range) is reimplemented per surface but all run on the one dictionary, so
the *data* cannot drift — logic-duplication only.

**Partial revision (2026-07-17, laterite-dev#532, part of arc laterite-dev#527) — the "no action" call
was itself asymmetric.** Python's `laterite.registry` facade had, since D2 of
dec-rust-engine-staged-adoption (2026-05-23), *bound* two of these walks —
`ancestor_chain`/`inherited_key_names` — to the Rust leaf rather than
reimplementing them; [[laterite-node]]'s `ts/registry.ts` genuinely
reimplemented both in TypeScript (its own comment said "matches the
Rust/Python check" — a hand-kept-in-sync copy, not a binding). So this row's
data couldn't drift, but Node's *logic* could have silently diverged from the
Rust tree walk it was meant to mirror. laterite-dev#532 closed that one asymmetry: two new
`#[napi]` fns (`registryAncestorChain`/`registryInheritedKeyNames`) call
`laterite_ags4_core::registry::{ancestor_chain, inherited_key_names}` directly,
the same leaf Python binds; the TS functions are now a pure native passthrough.
Deliberately not total convergence — `isKeyStatus`/`keyHeadings`/`childGroups`
stay local TS views (Python's own `registry.py` keeps the equivalent
Python-side too), so the register's broader "logic-duplication only, no
action" call still stands for the rest of the relationship logic on both
surfaces. See [[laterite-node]].

## The Rule-explainer catalogue (#1) — why it's curated, not generated

`web/public/rules-catalogue.json` (rendered by `RuleExplainer.tsx`) is a
**hand-curated, user-friendly** reference: per AGS rule, a plain-English title +
"what it checks" + a severity summary + fixable flag, plus a subset of the O-N
observations **rewritten for users** (e.g. "a degree symbol will not block your
file"). It is NOT the rule logic — that is single-sourced in
`laterite-ags4-validator/src/rules/*.rs` — and it is NOT verbatim
`OBSERVATIONS.md`: the texts serve different audiences (engineering record vs
end-user gloss). So it's intentionally hand-maintained, not generated.

**Content coverage:** the catalogue carries **34 of the 39** `OBSERVATIONS.md`
observations (the audit's "O-37/38/39 missing" was imprecise — those were already
present). This session added the two genuinely user-facing gaps: **O-20** (Rule 14
— TRAN_AGS isn't checked against the dictionary edition) and **O-34** (Rule 13 — a
non-CSV / empty file is reported as "not AGS4", not as missing groups). The **5
still absent are internal dev/roadmap `[NOTE]`s** correctly kept out of a
user-facing explainer: O-25, O-28, O-29 (effective-dict / `--dict` architecture)
and O-35, O-36 (parity-harness internals). A full editorial review of every note's
wording + coverage is an owner task (the catalogue is a curated user view, not an
automated sync — generating it would flatten the curated wording).

**Update (#197, 2026-06-22) — a gated single source now exists.** The "curated, not
generated" stance above is superseded for the *metadata* (it always was for the rule
*logic*). The editorial catalogue moved to `rust-packages/laterite-ags4-validator/data/
rules_meta.json` (the curated per-rule title / checks / severity / fixable / cited O-N),
**compile-time-embedded** and **gated**: `laterite_ags4_validator::catalogue` tests assert
it covers *exactly* the 27 rules the engine emits (no phantom — the old web copy carried a
no-op `12` and a non-existent `16a`) and that `fixable` matches the fix engine
(`FIXABLE_RULE_LABELS`); `tests/test_observations_faithful.py` (dev satellite) asserts
every cited O-N exists in the canon. It is surfaced read-only via `lat rules` and
`laterite.list_rules()`. The curated *wording* is preserved (the source IS the prose) — so
generating from it does not flatten anything.

**Row #1 is NOT yet closed.** This PR adds the gated source and points the CLI/Python at
it, but `web/public/rules-catalogue.json` still serves its **old hand copy** — which is now
genuinely *divergent* from `rules_meta.json` (it keeps the phantom `12`/`16a`, rule 4's
stale `fixable: false`, and rule 16 without O-43). So there are temporarily two live copies,
the new one correct + gated and the web one stale. **Pending (#202):** repoint
`web/public/rules-catalogue.json` to be generated from `rules_meta.json`, deleting the
divergence and closing register row #1.

## New single source: sensitive headings (2026-06-21)

`rust-packages/laterite-ags4-core/data/sensitive_headings.json` classifies every
AGS4 heading that carries identifying data (`project_id`, `project`, `client`,
`contractor`, `personnel`, `lab`, `accreditation`, `location_id`, `coordinate`,
`geology` — named formations/BGS codes, location-revealing offshore —,
`method`, `remark`, `freetext`) plus a default `scrub_policy` per category. It is
**generated** from `ags_dictionary.json` by `tools/gen_sensitive_headings.py`
(category rules over each heading's code + description, plus a curated overlay for
the vendor-custom cases the rules can't infer — discovered by an exhaustive scan of
the real corpus, `output/audit_leaks.py`), and **gated** by
`tests/test_sensitive_headings_faithful.py` (dev satellite) (regenerate == committed) — the same
generate→gate pattern as the dictionary and observations. It replaces the web
Anonymiser's lone hand-maintained regex: both consumers now read it —
[[laterite-ags4-corpus-qa]]'s `censor` and the **web `Anonymiser`** (via
`web/src/lib/sensitive.ts`, synced to `web/public` by `scripts/sync-sensitive.mjs`).
One list of *what is sensitive* — and, since laterite-dev#581 (2026-07-18), one engine that
acts on it, too. Phase 1 moved the corpus `censor` off its own category→action
mapping onto a `Policy` resolved into the shared `laterite-ags4-censor` engine
leaf; Phase 2 added a `censor` export to the engine wasm ([[laterite-ags4-wasm]])
that the browser Anonymiser now calls at Download instead of its own TS scrub
(deleted). Both divergence axes — *what* is sensitive and *how* it gets
scrubbed — are closed. See [[dec-ags4-censor-leaf]].
